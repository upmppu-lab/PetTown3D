# 시설 방문 중 주민·펫 동시 도착 — 2026-10-26

## 이번에 바뀐 동작

기존에는 주민만 접수대·테이블·수납대에 도착하면 서비스가 진행됐습니다. 이제 동행 가능한 강아지·페럿은 실제 펫까지 해당 단계의 대기 지점에 도착해야 접수·작업 시간·결제·퇴장이 진행됩니다.

- 주민은 기존 시설 이동 로직으로 목적지에 도착한 뒤 기다립니다.
- 펫은 같은 방의 이동 가능한 지점을 별도로 검색합니다. 계산대·테이블 안으로 들어가지 않고 주인 주변에 서며, 실내 단계에서는 실내 경계 안의 지점만 선택합니다.
- 펫 에이전트·경로·높이·단계·월드 변경 번호·대기 지점과의 실제 거리를 확인합니다.
- 펫이 뒤처지거나 사라지면 `펫 도착 대기`를 표시합니다. 작업 시간과 수납을 기다리며, 기존 180초 방문 종료 보호는 유지합니다.
- 새 단계나 저장 복원 직후에는 이전 단계의 도착 기록을 재사용하지 않습니다. 새 오브젝트와 실제 위치를 다시 확인합니다.
- 동행 모델이 없는 고양이·토끼의 기존 시설 이용은 유지합니다. 이 두 종의 실제 3D 도착을 확인하는 기능까지 구현한 것은 아닙니다.
- 기존 산책 선택은 방문이 끝난 뒤에도 유지됩니다. 서비스가 다른 펫을 동행 대상으로 선택하더라도 사용자 산책 선택 값을 덮어쓰지 않습니다.

## 실제 검증

1. Unity 컴파일 및 최종 Play Console 오류 0건.
2. 현재 실제 펫샵의 바닥/평탄화 정보·NavMesh·계산대/테이블 장애물을 그대로 사용하고, 그 위치에 렌더러와 충돌체가 없는 별도 시설 메타데이터를 만들었습니다. 사용자 저장 데이터와 별도인 비활성 테스트 게임 인스턴스의 주민 1명/강아지 1마리로 테스트했습니다. 카페·병원을 새로 건설하거나 지형을 변경한 검증은 아닙니다.
3. 최종 코드로 카페 입구→접수→조리→테이블/식사→수납→퇴장, 병원 입구→접수→검진대→예방검진→수납→퇴장을 실제 이동으로 통과했습니다. 각 단계의 주민/펫 좌표를 `paired-live-trace.txt`에 기록했습니다.
4. 테스트 펫을 정지시켜 주민만 도착했을 때 단계 진행과 작업 시작이 차단됨을 확인했습니다. 조리 중 펫을 떨어뜨렸을 때 남은 시간이 멈추고, 결제 단계에서 펫이 떨어져 있으면 실제 UI 콜백으로도 수납되지 않는 것을 확인했습니다.
5. 조리 진행 데이터를 디스크에 JSON으로 저장한 뒤 시설 런타임/펫 오브젝트를 정리하고, 파일을 다시 읽어 기존 `LoadProgression`으로 복원했습니다. 산책 선택·일일 산책 XP·소모품 사용 표시·남은 작업 시간이 보존됐으며, 복원 직후 실제 재도착 전 작업/수납 판정은 준비되지 않은 상태였습니다. 사용자 PlayerPrefs 슬롯을 테스트용으로 교체하지 않았습니다.
6. 복원한 방문을 완료한 뒤 카페 70 + 검진 140 = 테스트 수익 210골드, 각 소모품 1개 사용(3→2), 영수증 2건을 확인했습니다. 재로드에 따른 중복 차감/중복 수익이 없었습니다. 종료 후 원래 에이전트 속도/정지 상태 복구도 확인했습니다.
7. 고양이·토끼의 기존 서비스 경로를 유지하는 분기, 비활성 주민 에이전트에 대한 동작 차단을 확인했습니다.
8. 1080×1920 실제 공통 UI의 `펫 도착 대기` 화면을 확인했습니다. TMP 넘침 0, 44 미만 버튼 0, 제목 바 알파 0.8 유지.
