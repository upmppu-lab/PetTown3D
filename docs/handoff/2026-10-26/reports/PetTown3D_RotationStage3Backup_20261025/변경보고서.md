# PetTown3D 3단계 — 건물 방향·출입구·도로 방향 추천

## 완료 범위
- 신규 건물에 논리 방향 0°(+Z), 90°(+X), 180°(-Z), 270°(-X) 도입. 건설 중 R은 90° 회전, 그 밖의 모드에서는 기존 카메라 초기화 동작 유지.
- 건설 미리보기의 사각 점유 영역과 출입구 화살표를 함께 회전. 기존 건물 위치/루트 회전을 소급 변경하지 않음.
- 주변 도로 중심선에 가까운 방향을 추천. 예: 수평 도로 북쪽 건물은 남향(180°), 남쪽은 북향(0°). R로 수동 회전한 뒤에는 자동 추천이 덮어쓰지 않음. 도로가 없어도 배치 가능.
- 1m 스냅은 유지. 이 단계에서 건물을 도로 쪽으로 이동시키거나 같은 줄로 재배치하지 않음.
- 신규 배치에만 모델 종류·보정·높이·방향·입구·점유 크기 정보를 붙임. 가구·상점 장식·신규 나무를 건물과 함께 회전.
- 기존 물고기 애니메이션 로직을 교체하지 않고, 새로 회전한 수조의 이동 좌표에만 회전 기저 적용. 신규 상점 수조를 만들 때 기존 물고기 관리 목록을 비우지 않도록 해당 신규 생성 경로에 한해 보완.

## 실제 모델 방향 확인
- 주민 주택 4종을 PreviewRenderUtility로 -Z/-X/+Z/+X 네 방향에서 렌더링. house_front_views.png 참고.
- 네 모델의 주 출입문이 원본 +Z 방향에 있음을 확인. 신규 모델을 정규화된 건물의 -Z 출입구 기준에 맞추도록 180° 모델 보정 사용.
- 건물 루트의 실제 Euler 값은 모델 정면 보정 때문에 논리 방향 표시와 다를 수 있음. 예: Home의 논리 북향 0°는 루트 yaw 180°.
- Inspector의 New Building Direction / Construction Definitions에서 건물 종류별 footprint, local entrance, base yaw, model yaw 보정 설정 가능.
- 주민 모델 순서는 SmallMedievalHouse, MedievalHouse, TwoStoryMedievalHouse, TwoStoryMedievalHouse_2. 선택적 variantModelYawCorrections / variantEntranceLocalOverrides로 각 모델을 개별 보정 가능.
- 공원·동물원의 출입구 기본 X 위치는 기존 울타리 생성 코드의 실제 게이트 위치(각각 1.5m / 약 1.571m)에 맞춤.

## 저장 호환성
- 기존 PlayerPrefs 키와 types/x/z, shopX/shopZ 등 기존 필드 유지.
- constructionVersion=2, shopPlacement, buildingPlacements만 선택적으로 추가.
- 새 기록에는 고유 ID, 기존 배열 인덱스, 건물 종류, 논리 방향, 모델 종류/높이/보정, 바닥 높이, 입구/점유 정보를 저장.
- 새 기록이 없는 구형 건물은 기존 CreateBuilding 경로로 로드. 기존 건물에 임의의 방향·ID를 소급 지정하지 않음.
- 신규 배치의 기록은 정의 설정을 나중에 바꾸더라도 기존 저장의 방향/모델 선택을 보존하도록 필요한 값을 복사해 보관.
- 구형 주민 주택은 원래 코드가 로드 때 모델/자식 yaw를 다시 무작위로 선택함. 이 기존 동작을 이번에 마이그레이션하지 않음. 신규 계획 배치만 고정 모델/방향을 보장.

## 검증 결과
- Unity 6000.6.6f1의 C# 컴파일 완료, 최종 콘솔 error 항목 0건.
- 방향/보정/직사각형 점유 회전/JSON 왕복/도로 양쪽 추천/수동 우선권/도로 없음 폴백/구형 저장 파싱: 기본 검사 73개 통과.
- 모델별 보정과 공원/동물원 게이트 오프셋 추가 검사 통과.
- 실제 Place()를 통해 4개 Home을 0/90/180/270°로 설치. 건물과 의자 위치 및 11×10 ↔ 10×11 점유 크기 일치.
- 실제 주민 주택의 모델 정면과 출입구 방향 내적 1.0 확인.
- 실제 신규 상점의 회전 카운터, 기존 수조 물고기 3마리 보존, 새 수조 물고기 3마리의 회전 좌표 기저 확인.
- 테스트 저장을 실제 Play 재시작으로 다시 로드해 신규 건물 5개의 ID/방향/높이/모델 유지 확인.
- 기존 5개 건물의 위치·루트 회전이 테스트 전후 동일함을 확인.
- 실제 게임 화면의 도로 추천 180° 및 출입구 화살표 표시 확인. 수동 변경 270° 유지, 도로 선택 시 화살표 숨김, 탐험 시 안내 숨김 확인.
- 실제 Play에서 NPC/동물 경로와 이동 속도 확인. NPC 이동/애니메이션 코드 블록과 강 렌더링 코드 블록은 원본과 동일. 기존 플레이어·물 셰이더·머티리얼·에셋 파일 해시 변경 없음.
- 테스트 건물과 도로는 Play 종료로 제거. 사용자 원본 저장 문자열을 byte-equivalent 문자열로 복원 후 일치 확인. 최종 Unity는 Play 중지 상태.
- 실제 키보드 R 입력 자체는 자동화 도구로 재현하지 못함. R에 연결된 회전 동작과 카메라 값 유지 및 수동 우선권은 메서드 실행으로 검증.

## 남은 범위/제약
- 4단계 종합 안전 검사(경사, 입구 폭, 통행로 연결성, 초록/노랑/빨강)는 아직 구현하지 않음. 현재 미리보기 색은 기존 자금 기준.
- 도로와 같은 줄로 위치 정렬하거나 연결 보행로를 자동 생성하지 않음. 기존 도로를 이동·재생성하지 않음.
- 현 세션에서 생성된 도로/초기 마을 길의 중심선을 조회함. 구형 저장에 경로가 없는 드래그 도로를 복원하는 기존 결함은 해결하지 않음. 도로 영속화는 5단계 별도 작업.
- 수입 주민 주택의 기본 입구 위치는 문 방향의 점유 영역 외곽 접근점. 정확한 문턱 좌표는 모델별 entrance override로 추가 보정할 수 있으며, 주택 내부 진입 가능 여부를 보장하는 것은 아님.
- 새 건물의 실제 NavMesh 접근성·통행로 보장은 4단계에서 검사 필요. 특히 기존 주민 주택의 콜라이더가 한 프레임 뒤 생성되는 구조와 NavMesh 재생성 타이밍은 별도 확인 필요.
- 모델 미리보기는 기존 평면 점유 박스를 유지. 주민 프리팹을 미리보기로 새로 렌더링하는 UI는 추가하지 않음.
- 장시간 연속 배치와 전체 성능 측정은 미수행. 같은 셀/도로 상태에서는 방향 검색을 캐시함.
