## 4단계 — 펫샵 초기 인테리어
신규 펫샵은 계산대·컴퓨터·의자·사료 진열대·장난감 진열대·강아지 쿠션·고양이 펫타워·RAT 케이지·새장·수족관·화분의 11종을 생성한다.
15×15m 원래 실내와 기존 3m 모듈 바닥/벽을 재사용했다. Kenney Building Kit의 2m 규격을 기존 3m 규격에 무리하게 섞지 않았다.
컴퓨터는 Kenney screen/keyboard/mouse 모델 조합, 사료장은 Mini Market shelf-bags 모델을 참조하는 새 wrapper prefab이다. 원본 FBX·텍스처를 교체하지 않았다.
전문 RAT 케이지·새장·수족관은 기존 조립형 가구를 재사용했다. 펫타워 전용 모델은 없어 기존 재질/프리미티브로 제작했다. 이들에 외부 전문 모델이 있다고 가정하지 않았다.
기존 저장 매장의 가구를 자동 교체·이동·추가하지 않는다. 구버전 저장은 기존 배치로 복원하며, 플레이어가 새 가구 목록에서 필요한 가구를 추가할 수 있다.
실제 Play에서 신규 매장 11개 생성과 정상 모델 크기를 확인했다.

## 추가 가구 배치 범위
가구 목록 14종: 기존 계산대·펫 쿠션·진열대·의자·테이블·화분 6종, 장난감 진열대·RAT 케이지·수족관·강아지 쿠션·새장·펫타워·컴퓨터·사료장 8종.
모두 기존 실내 0.5m 격자, 4방향 회전, 실제 형상의 미리보기, 충돌·통행 검사와 저장 경로를 공유한다. 기존 의자에 적용되던 미세 무작위 yaw는 플레이어 신규 배치에 적용하지 않는다.
컴퓨터는 계산대/테이블의 실제 표면 높이에 설치하며 바닥 설치를 거부한다. Play에서 펫타워 배치와 컴퓨터 바닥 거부/계산대 허용을 확인했다.
수족관 회전 시 내부 물고기 이동 중심/방향도 함께 처리한다. 미리보기는 실제 가구·재고·NPC를 등록하지 않으며 임시 재질을 해제한다.
기존 가구 이동·삭제 UI는 새로 임의 추가하지 않았다. 현재 플레이어 가구 배치는 기존 기능 범위대로 펫샵을 대상으로 한다.

## 5단계 — 실제 증축
펫샵 관리 → 증축하기 → 로컬 왼쪽/오른쪽/앞쪽/뒤쪽 → 반투명 면적/벽 미리보기 → 비용 확인 후 확정.
설정 클래스에서 3m 증축 깊이, 종류별 면적당 비용, 최대 크기를 조정할 수 있다. 기본 펫샵은 20골드/m², 15m 변에 3m를 추가하면 45m²/900골드다. 레벨 제한을 추가하지 않았다.
실내 로컬 중심·크기·원래 크기를 선택적 저장 필드로 관리한다. 기존 건물 루트 위치/회전/Scale은 유지하고, 추가 바닥 타일·갱신 벽·지붕으로 실제 실내를 확장한다. 기존의 앞/오른쪽 개방형 실내 보기 방식은 유지한다.
확장 면적은 가구 격자, 건물 충돌, 도로 연결 조회, 실제 출입구 좌표, 지면 높이와 NavMesh 갱신에 반영한다.
강/물, 다른 건물·도로, 지형 높이 차, 경계, 현재 캐릭터, 기존 통행로를 검사한다. 자연물이 있으면 노랑으로 표시하고 확정을 막는다. 평탄화 영향까지 고려해 2.5m 여유 범위를 보수적으로 검사한다.
증축 과정에서 자연물·도로를 자동 삭제하지 않는다. 별도의 ‘증축 주변 자연물 정리’ 목록에서 플레이어가 선택한 자연물만 제거하며 안정 ID를 저장한다. 장식 가구/도로/다른 건물은 이 정리 대상이 아니다.
증축 준비 중 일반 저장을 보류한다. 실제 바닥 연결을 NavMesh에서 확인한 뒤 비용을 차감하고 저장한다. 실패하면 새 셸·면적·지형 정점·높이 구역·바닥 등록을 복구한다.
검증: 15×15→18×15m, 45m² 증가, 900골드 차감, 기존 가구 10개 기록과 건물 위치/회전 유지, 재실행 복원. 결제 조건 실패 주입에서도 지형 해시/면적/기존 가구 기록이 복구됐다. 이 실패 테스트 중 기존 주문·자동 저장은 계속 실행되어 코인/명성/실패 주문의 일반 게임 기록은 진행됐다.
증축 창은 매장에 초점을 맞추고 닫으면 이전 초점을 복원한다. 카메라 이동 알고리즘은 교체하지 않았다.
카페/병원의 비용·소유/저장 확장 기반은 공유하도록 준비했으며 실제 증축 UI·개별 시설은 지시대로 펫샵부터 지원한다. 건물 이전은 구현하지 않았다.

## 6단계 — HUD
Kenney 9-slice + 한국어 동적 TMP 폰트의 반응형 HUD를 추가했다.
실제 Day/주민/명성/재화/캐릭터 초상, 주문·판매, 알림, 탐험/건설/가구/캐릭터/펫샵, 저장·지붕 기능에 연결했다. 일반 아이템 가방·설정·주민 상세 등 실제 데이터/기능이 없는 메뉴는 가짜로 만들지 않았다.
기존 HUD는 보존하고 ‘기존 UI / 새 UI’로 전환할 수 있다. 기존 건설 도구/캐릭터 상세 패널은 원래 기능을 유지한다.
가로 화면 및 720×1280 세로 화면 캡처로 겹침/잘림을 확인했다. 실제 모바일 터치 기기 검증은 하지 않았다.
전체 에셋 refresh에서 발견된 TMP include 누락은 설치된 Unity uGUI 패키지의 Essential Resources에서 없던 .cginc 4개만 복원했다. 기존 TMP 소스는 덮어쓰지 않았다.

## 7단계 — 별도 자연환경 비교
Assets/PetTown3D/EnvironmentTests/EnvironmentComparison.unity를 만들었다.
게임 인스턴스/PlayerPrefs 없이 기존 실제 지형·강·강둑 메시와 자연물 55개를 복사한 별도 씬이다. A/B 버튼으로 같은 카메라에서 기존/새 렌더링을 비교할 수 있다.
메뉴 PetTown → Environment → Open Comparison Scene으로 열 수 있다.
기존 강 표면 기반 개선안과 이미 설치된 다른 물 셰이더의 의존성/호환성을 분석한 결과, 기존 곡선 메시·깊이 정점·거리 UV 기반 흐름을 유지하는 개선안을 적용했다. 새 물 시스템으로 경로/충돌을 교체하지 않았다.
실제 비교 캡처에서 발견한 잎 검은 면은 새 머티리얼의 알파 잘림으로 해결했고, 과한 잔디 채도를 낮췄다.

## 8단계 — 마을 자연환경 적용
별도 GroundNatural/RiverNatural 셰이더와 런타임 재질 복사본을 사용한다. 원본 셰이더/머티리얼/텍스처를 교체하지 않는다.
잔디·흙·식생 레이어의 사진 대비를 낮추고, 강 중앙 청록색/얕은 물 색상 및 좁은 경계 표현·강둑 흙/모래/자갈을 유지·보정했다. 흐름은 원래 강의 누적 거리 UV를 따라 천천히 이동한다.
Nature MegaKit의 나무 2종·수풀·꽃수풀·잔디·꽃·바위 모델을 새 wrapper prefab으로 참조한다. 기존 자연물 루트 위치·콜라이더·NavMesh 장애물은 보존하고 자식 렌더링만 바꾼다. 실제 마을에서 294개를 스타일링했다.
펫샵 관리의 ‘환경 스타일 전환’으로 기존 렌더링으로 돌아갈 수 있다. 새 스타일은 코드 설정으로 끌 수 있다.
검증: 전환 전후 지형 정점 수 12,321/강 정점 수 14,421 및 기존 콜라이더 ID 목록 일치. 원래 경로·UV·지형 정점은 스타일 전환에서 수정하지 않는다.
실제 에셋 다운로드가 추가로 필요하지 않아 설치된 팩만 사용했다.

## 9단계 — 최종 검증 및 한계
Unity C# 컴파일 및 Play 확인, 마지막 Console error 조회 0건.
추가 펫타워·컴퓨터를 포함한 가구 15개의 전체 저장 기록·월드 위치·모델 위치가 재실행 후 정확히 일치했다. 증축 면적과 개별 자연물 제거 기록도 복원됐다.
NPC/동물 NavMeshAgent 9개체를 두 시점에서 관측했으며 모두 실제 위치가 변했다. 기존 NPC 이동/애니메이션 코드는 보존했다.
증축 부지 거부, 성공 결제, 실패 복구, 원래 가구 보존, 저장 복원, 가구 지지면, HUD 전환, 세로 배치, 원본 환경 전환을 확인했다.
이번 단계에서는 실제 키보드 R 입력을 자동 누르지 않았다. 앞 단계에서 동일 회전 함수의 90/180/270/0도 순환과 화면 버튼 호출을 검증했으며 UI/코드는 같은 경로를 사용한다.
Windows/모바일 배포 빌드, 실제 모바일 터치, 장시간 성능/모든 증축 조합/모든 가구 조합은 미검증이다. 기존 일부 펫의 애니메이션 경고나 .blend 에셋의 Blender 미설치 문제를 이번 범위에서 전체 해결했다고 주장하지 않는다.
