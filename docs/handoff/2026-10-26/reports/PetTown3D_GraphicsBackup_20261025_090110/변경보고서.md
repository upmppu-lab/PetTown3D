- Unity 버전: ProjectVersion.txt의 6000.6.6f1.
- 작업 전 Git HEAD: d92b1b8 (Merge laptop and GitHub project). 원격 저장소와 최신 동기화되었는지는 검증하지 않음.

## 변경 파일
1. Assets/PetTown3D/Scripts/PetTownGame.cs
   - 도로: 오프셋 리본을 선분별 둥근 영역의 합집합으로 생성하는 20cm 격자 메시로 변경. 같은 드래그 안의 급커브·헤어핀·자기 교차를 중복 면 없이 처리.
   - 중복 입력점 제거, 경로 안쪽으로만 모서리 보간, 최대 25cm 간격으로 샘플링. 이전 전역 Catmull-Rom 파라미터화의 오버슈트와 긴 경로의 샘플 누락 방지.
   - 건물 사각 영역을 폴리곤에서 정확히 빼서 개별 정점을 서로 다른 벽으로 밀어내던 문제 제거. 수입 주택은 기존 콜라이더의 범위만 읽어 도로 차단에 사용.
   - 등록된 개방형 건물의 -Z/+X 입구 면에 가까운 끝점만 연결하고, 바닥 높이로 시각적 경사 연결. 건물은 변경하지 않음.
   - 모든 도로 정점은 실제 TerrainLayer 레이캐스트 높이를 따름. UV는 월드 XZ / 2.5m로 통일하여 끝·급커브의 텍스처 압축 방지.
   - 미리보기 갱신은 최대 10Hz. 기존 드래그 입력·가격·저장 호출 유지.
   - 강: 기존 중심선·폭·곡선·지형 구조 유지. 수면 가로 샘플 수 12→32, 지형과 수면의 높이 차를 정점 색으로 전달.
   - 강둑은 실제 지형 메시를 공유하는 시각 레이어. FlattenTerrain 이후에도 지형 메시와 일치. 지형과 충돌을 별도로 새로 생성하지 않음.
2. Assets/PetTown3D/Resources/Materials/PetTownRoadSurface.shader (+ .meta)
   - 기존 흙길 텍스처 재사용. 기존 리본 텍스처의 투명 좌우 테두리가 교차로 내부에 반복되지 않도록 중앙 부분을 좌우 대칭으로 샘플링.
   - 약 12cm의 메시 경계 페이드와 고정 월드 UV 사용. 기존 흙길 머티리얼은 다른 오브젝트가 계속 사용.
3. Assets/PetTown3D/Resources/Materials/PetTownRiverSurface.shader (+ .meta)
   - 넓은 투명 띠 제거. 중앙은 불투명한 청록색, 물가는 폭과 지형 깊이에 따른 얕은 물 색. 약 8cm 끝부분만 페이드.
   - 누적 중심선 거리 UV와 시간 위상으로 약 0.175m/s의 물결 이동. 월드 축 방향 스크롤이나 Clamp 텍스처에 의존하지 않음.
   - 기존 지형 흙 텍스처에 모래·젖은 흙 색상과 작은 자갈 무늬를 혼합. 자갈은 셰이더 표면 무늬이며 별도 돌 오브젝트/충돌체가 아님.
   - 강둑은 수면보다 먼저 렌더링. 지형의 원래 삼각형을 공유하므로 별도 덮개 메시가 지형을 파고들어 생기는 틈 방지.
   - Resources 경로로 로드해 빌드 시 Shader.Find만 사용하는 경우의 셰이더 누락 위험 방지.

## 원인
- 이전 도로는 급커브에서도 좌우 오프셋을 단순히 연결해 안쪽 가장자리가 접히거나 교차할 수 있었음. 끝부분 폭 축소는 이 문제를 해결하지 못함.
- 건물에 들어간 정점만 행별로 벽에 투영하여 끝의 두 가장자리가 다른 방향으로 변형될 수 있었음.
- UV의 가로값을 줄어든 폭에 그대로 할당하여 캡과 커브에서 텍스처가 압축/늘어남.
- 강은 폭의 17%(약 1.8m)씩 양쪽을 투명 처리하고 텍스처를 세로까지 Clamp하면서 무한 스크롤하여 흐릿한 경계와 정지/늘어짐 문제가 생길 수 있었음.

## 검증 결과
- Unity가 생성한 Assembly-CSharp.rsp의 참조·define를 사용하여 전체 런타임 C# 소스를 Roslyn으로 컴파일: exit 0, 오류 없음. 출력은 이 백업 폴더에만 생성. Unity 자체의 전체 에디터/플레이어 빌드 완료를 의미하지 않음.
- 기존 영역에서 deprecated API 및 unreachable code 경고가 있음. 범위 밖 코드라 변경하지 않음. compile-results.txt 참고.
- 실제 도로 생성 메서드를 추출하여 Unity의 Vector2/Vector3/Mathf 연산과 메모리 Mesh 대역, 결정적 경사 높이로 독립 실행:
  직선/직각/헤어핀/자기 교차/중복 좌표, 삼각형 방향, 내부 구멍/중복 면 샘플, 둥근 캡 면적, 고정 UV, 정점 높이, 건물 영역 클리핑, 입구 스냅/높이 연결 통과.
  실제 Physics.Raycast와 Unity Mesh GPU 업로드는 대역으로 대체되어 검증 대상이 아님. geometry-results.txt 참고.
- 백업과 비교하여 BuildFenceRing부터 파일 끝 전체(건물·NPC·저장 포함), Height/Ground/IsWater, Update의 캐릭터 관련 영역이 동일함을 확인. GroundBlend.shader도 SHA256 동일. preservation-results.txt 참고.
- git diff --check 통과.

## 확인하지 못한 부분과 남은 한계
- 실행 중인 Unity는 확인했지만 화면 제어 연결이 두 차례 시간 초과됨. Unity 에디터가 임시 검사 파일을 가져오지 않아 에디터 검사 실행은 확인되지 않음. 임시 파일은 프로젝트에서 제거하고 이 폴더에만 보존.
- 셰이더의 Unity GPU 컴파일, 실제 게임 화면, 드래그 반응/성능, 물결의 시각적 방향·속도, 빌드 결과, NPC·캐릭터의 플레이 회귀 테스트는 확인하지 못함. 그래픽 개선이 실제 화면에서 성공했다고 단정하지 않음.
- 서로 다른 드래그로 만든 기존 도로 객체끼리는 하나의 메시로 전역 병합하지 않음. 이 경우의 겹침/투명 정렬은 플레이에서 추가 확인 필요.
- 입구 자동 연결은 기존 buildingFloors에 등록된 -Z/+X 개방형 건물 기준. 임의 회전 수입 주택은 입구 메타데이터가 없어 문 위치까지의 자동 연결을 보장하지 않음. 기존 콜라이더 내부는 차단.
- 기존 IsWater의 게임 판정 폭과 시각적 수면 폭은 일치하지 않음. 이 차이는 이동/배치 동작 보존을 위해 변경하지 않음.
- 기존 저장 결함: SaveData에 드래그 도로 좌표가 없고 SaveGame은 도로 부모 원점만 저장하며 LoadGame은 types==8을 건너뜀. 따라서 원래 코드에서도 드래그 도로가 재접속 시 복원되지 않음. 저장 시스템 수정 금지 조건에 따라 수정하지 않음.
