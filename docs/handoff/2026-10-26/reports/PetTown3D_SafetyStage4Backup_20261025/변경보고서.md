# PetTown3D — 4단계 건설 안전 검사
2026-10-25 / Unity 6000.6.6f1 / C:\UnityProjects\PetTown3D

## 범위와 복구
기존 격자 및 방향 시스템에 안전 검사를 추가했다. 5단계 도로 정렬/연결 보행로/보너스와 6단계 도로 모드는 시작하지 않았다. 색상 판정용 도로 조회만 추가했다.
수정 전 Git HEAD d92b1b8 및 미커밋 변경을 확인했다. 이 폴더에 단계 시작 시 소스 3개, Git 상태/HEAD, 소스·셰이더·머티리얼 해시와 PlayerPrefs 저장 JSON을 백업했다. 전체 프로젝트 백업은 아니다.
최종 해시 비교에서 기존 파일은 PetTownGame.cs, PetTownRoadPath.cs만 변경됐다. 기존 NPC 이동/애니메이션 코드 구간, Height~BuildWorld 구간, 플레이어 제어 파일 및 기존 셰이더·머티리얼은 원본과 같다.
Play 테스트용 건물/도로/장애물은 씬에 저장하지 않았다. Play 종료 후 PetTown3D_Save 문자열 및 시작 자본 플래그를 원본과 동일하게 복원했다. 현재 Play 중지 상태다.

## 변경 파일
프로젝트의 아래 경로를 기준으로 한다.
- Assets/PetTown3D/Scripts/PetTownGame.cs: 기존 격자 미리보기와 Place 확정에 검사 연결. 거부 시 비용 차감/생성/저장 전 반환. 기존·신규 점유 영역/입구, 실제 지형/물/물리 장애물, 현재 NPC·플레이어 위치를 읽는다. 기존 평탄화가 강둑/기존 바닥·입구를 훼손하는지도 확인한다. 모델 맞춤 코루틴 뒤 NavMesh를 갱신하고 신규 계획 주택 및 신규 호수에 carving 장애물을 적용한다. 기존 NPC 행동은 교체하지 않는다. 임시 미리보기는 NavMesh 수집에서 제외. 기존 건설 안내에 색상과 한글 사유 표시.
- Assets/PetTown3D/Scripts/PetTownRoadPath.cs: 최근접 도로 폭 및 사각형-도로 구간 겹침 조회 추가. 도로 메시/UV/머티리얼/저장 형식은 유지.
- 신규 Assets/PetTown3D/Scripts/PetTownPlacementValidator.cs: 설정, 검사 컨텍스트, 판정 결과 및 독립 검사기. 건물/도로 중복, 물, 경사/높이차, 입구, 최소 통로, 평탄화 영향, 장애물, 통행로 및 도로 연결 검사. 같은 위치는 0.3초 캐시, 확정 때는 최신 컨텍스트/높이를 강제 재검사.
- 신규 Assets/PetTown3D/Scripts/PetTownNavigationQueries.cs: 현재 native NavMesh 경로와 가상 점유 영역 비교, 네 모서리를 통한 우회 검사. 검사 자체는 NavMesh/에이전트를 수정하지 않는다.
- 신규 Assets/PetTown3D/Resources/Materials/PetTownPlacementPreview.shader: 건물 미리보기 전용 URP 셰이더. 물/바닥에 가려져 색상 표시가 사라지는 것을 방지한다. 기존 물 렌더링에는 적용하지 않는다.
신규 파일 3개의 .meta도 추가했다. 기존 파일 이름/저장 형식은 바꾸지 않았다.

## 동작 및 설정
초록: 도로 연결 + 설치 가능. 노랑: 도로 없음 + 설치 가능. 빨강: 설치 불가와 한글 사유.
도로는 필수 조건이 아니다. 기존 건물 위치/회전은 변경하지 않는다. R키 및 도로 방향 추천은 이전 단계 기능을 유지한다.
Construction Safety 기본값: 최대 경사 18도, 최대 높이차 2m, 최소 통로 1.2m, 입구 깊이 2m, 도로 가장자리 연결 거리 2m. Inspector에서 조정 가능.

## 검증
- Unity C# 컴파일 완료, 최종 Console error 조회 0. 신규 셰이더 isSupported=true 및 ShaderUtil 오류 없음.
- 독립 검사 18개 분기와 캐시/강제 재검사 통과. validation-snippets.txt 및 test-results.json에 결과/실행 코드 보관.
- 멀리 떨어진 임시 native NavMesh 데이터에서 넓은 땅 우회 허용, 좁은 다리 차단 거부 확인. 임시 데이터는 finally에서 해제.
- 실제 Play에서 Building/Water 거부 시 건물 수, 코인, 저장 문자열 유지.
- 허용 미리보기 후 물리 장애물을 추가하고 Place 실행: Obstacle로 재판정, 비용/저장 유지.
- 실제 도로 없는 후보는 노랑/NoRoad, 입구 근처 임시 도로 추가 시 초록/Connected. connected-green.png 참조.
- 물 위 빨강 미리보기와 한글 거부 안내 확인. water-blocked-red.png 참조.
- 도로 없이 Home을 (-40, 1.42, 70)에 설치: 건물 수 +1, 코인 -600, 격자 위치 및 메타데이터 확인.
- 도로 없이 주택을 (-70, -0.48, -75)에 설치: 지연 갱신 후 BoxCollider와 carving 장애물 존재, 갱신 대기 해제 확인.
- 기존 건물 5개의 위치/회전은 전후 동일. 배치 후 NPC 8명과 동물 3마리 모두 onNavMesh/hasPath이며 속도 양수(약 0.9~3m/s).
- 작은 현 씬의 대표 강제 검사는 초기 약 34~66ms, 예열 후 약 5ms. 대규모 부하 검증은 하지 않았다.
- 캡처용 카메라는 원래 위치/회전 복원 확인. 테스트 동안 켠 백그라운드 실행도 기존 false로 복원.
- 원본 저장 문자열 및 자본 플래그 복원 확인, 테스트 건물은 Play 종료로 제거.

## 한계 및 후속
현재 경로 + 가상 사각형 + 모서리 우회를 사용하는 보수적 검사다. 미래 전체 NavMesh를 사전 베이크하는 완전한 보장은 아니다. 다른 우회가 가능해도 거부할 수 있다. 경사/평탄화는 약 1m 샘플 기준이며 열린 공원 등도 전체 예약 영역을 보호한다.
MCP로 실제 Place/미리보기/UI 진입점을 실행했다. 물리 마우스·키보드 전체 수동 시나리오, 장시간 플레이, 모든 모델 변형은 검증하지 않았다.
기존 도로 저장은 kind=8 위치 항목만 저장하고 로드시 건너뛰는 문제가 있다. 이번 단계에서 저장 형식을 바꾸지 않았으며 5단계 도로 복원/연결에서 처리해야 한다.
기존 건물을 재배치하거나 기존 저장을 새 형식으로 재작성하지 않았다.
