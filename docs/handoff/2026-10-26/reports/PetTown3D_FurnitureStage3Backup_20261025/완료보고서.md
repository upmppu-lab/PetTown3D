# 통합 개발 3단계 — 가구 목록·펫샵 관리 및 격자 배치
2026-10-25
사용자가 추가한 가구 격자/상하좌우 회전/미리보기 요구를 저장 기반과 함께 구현했다.
변경: PetTownGame.cs(소유/입력/검사/생성/선택적 저장 연결), PetTownCatalogWindow.cs(관리 행동/가격/면적 표기 일반화).
신규: PetTownInteriorState.cs, PetTownFurniturePlacement.cs, PetTownFurniturePlanner.cs, PetTownFurnitureGrid.cs 및 각각 .meta.
기존 캐릭터 이동/애니메이션, NPC 행동, 지형·강 생성 핵심 구간은 수정하지 않았다. 내부 가구 렌더링/수족관 복원을 위해 tankFish의 전역 초기화 대신 해당 가구의 물고기만 정리하도록 연결했다.
가구 목록은 기존 실제 prefab 6종을 검색/카테고리/가격·면적/실제 썸네일로 보여준다. 펫샵 관리는 기존 펫 재고 입고, 지붕 전환, 저장 동작을 재사용한다. 일반 아이템 인벤토리는 만들지 않았다.
새 가구는 펫샵 로컬 0.5m 격자에 스냅하며 R키와 화면 버튼이 동일한 90도 회전 함수를 사용한다. 기존 임의 ±8도 모델 회전은 새 플레이어 배치에는 적용하지 않는다. 기존 가구의 위치/회전은 보존한다.
실제 바닥에 제한된 격자, 회전 모델, 초록/빨강 점유 테두리와 한글 사유를 표시한다. 실내 경계, 벽/다른 가구, 출입구, 현재 캐릭터/동물 및 기존 NavMesh 통행로를 검사하며 확정 때 강제 재검사한다. 도로/건물 지형을 변경하여 가구를 맞추지 않는다.
가구 저장은 선택적 interiorVersion=1/interiors 확장으로 건물 소유 ID, 기존 저장 인덱스, 로컬 위치/회전, 모델 회전·높이, 종류, 기본/추가 가구 상태를 저장한다. 예전 저장은 기존 기본 가구를 생성하고 새 필드를 추가할 수 있다. 새 레코드가 있으면 기본 가구를 제거한 뒤 저장 가구만 복원하여 중복을 방지한다. 알 수 없는 레코드는 보존한다.
검증: Unity C# 컴파일, Console error 조회 0. 회전된 방 좌표의 스냅, 90도 점유 영역 교환, 입구/벽 경계 거부 검사 통과.
실제 Play에서 기존 가구 13개의 기록과 세계 위치가 재실행 후 정확히 일치했다. 새 의자를 (로컬 2,0.12,-2)에 90도로 배치했고 모델 내부 yaw=0, 코인 -50을 확인했다. 기본 상태가 아닌 추가 가구로 저장됐다.
추가 의자 포함 14개 가구의 전체 기록/실제 위치가 재실행 후 정확히 일치하며 중복 생성되지 않았다.
가구 카테고리 좌석=2, 의자 검색=1, 펫샵 관리 항목=4를 확인했다. 기존 강아지 입고는 코인 -120/재고 +2, 지붕 전환 정상.
회전 함수 4회가 90/180/270/0도를 반환하고 화면 버튼도 같은 함수를 호출했다. 실제 물리 R키 입력은 자동화하지 않았다.
설치 가능 미리보기 후 임시 장애물을 추가하고 Place를 실행하면 FurnitureObstacle로 거부하며 가구 수·코인·저장 문자열이 모두 유지됐다.
격자 메시 248정점, 점유 테두리 16정점을 확인했다. 밝은 바닥에서 보이도록 대비를 보완했다. 생성 중 컴포넌트 null 판정 문제는 수정했다.
현재 플레이어 배치 UI는 기존 기능 범위대로 펫샵을 대상으로 한다. 다른 실내의 기존 기본 가구도 소유·저장하지만, 건물 이전/가구 이동·삭제·카페 관리 기능을 임의로 추가한 것은 아니다.
장시간/모바일 기기/모든 모델 변형은 미검증이다. 통행로 검사는 현재 NavMesh와 가상 점유 영역을 이용하는 보수적 방식이다.
테스트 종료 후 Play 중지, 원본 저장 문자열/자본 플래그 복원, 씬 isDirty=false를 확인했다. 이후 신규 인테리어 작업은 별도 단계로 진행한다.
